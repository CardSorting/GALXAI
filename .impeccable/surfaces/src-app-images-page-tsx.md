# Image studio — surface brief

## Scope and mode

Operate. `/images` lets a person describe an image, select supported settings, generate, inspect completed work, and return to saved images. Hosted image creation was explicitly restored at the user's request on 2026-09-10; the earlier retirement decision does not govern this surface. This is private maintainer context, not public product documentation. Do not import its design rationale, implementation details, or verification diagnostics into public UI, metadata, browser assets, or responses.

The September 13 results and ergonomics refinements extend the existing GALX identity recorded in `DESIGN.md`: restrained indigo actions, dark panels, inherited sans-serif typography, compact controls, and subtle borders. Blank space is deliberate; user-generated work supplies the visual content. The API Request Inspector's restriction on generated-content libraries remains scoped to that inspector. Neither the global design system nor its sidecar is rewritten for this surface.

## Direction and first viewport

The [shared product header](src-components-dashboard-navigation-tsx.md) lives in the root layout and keeps its position through Home, Images and Sites navigation. Studio navigation below it remains Create / My images / Favorites. Leaving `/images` still unmounts the workspace and its in-memory session results; header continuity does not add durable history.

The workspace leads with composition at the left and a blank results canvas at the right. A compact title and persistent Create / My images / Favorites navigation establish the workflow. The creation pane groups prompt, aspect ratio, and count in that order. Controls scroll independently on desktop while Generate remains available at the bottom.

The initial Create view shows **Your creations**, **0 images this session**, the **Image / Grid** toggle, and an empty dark canvas. It contains no starter images, inspiration cards, or starter prompt actions. The blank canvas has an accessible empty-state description without visible filler content. The separate saved-library view retains its existing copy and empty states.

The desktop composer is 328px wide, becomes 300px below 1200px, and grows to 360px from 1600px. The canvas content is bounded at 1480px. Image uses a large bordered stage with a desktop height clamped between 300px and 640px. A selectable filmstrip below it appears when more than one image is available. Grid uses compact square thumbnails with numbered positions and single-line prompt captions, leaving the workspace available for successive batches. Visible previous/next buttons, an image position, and a separate Latest image action make continuous browsing discoverable.

Observed local styling uses the incumbent dark background and panels, an indigo primary action (`#4f46e5`), light indigo selected states, and readable muted text (`#a9aebc`). Controls generally use 8px corners; larger containers use 12px. The result-view toggle's inner buttons and thumbnail number labels use 4px corners. The studio title is 20px on desktop; Your creations is 18px, library section titles are 24px, and body/control text is mostly 13–14px with 11–12px supporting labels. These describe this surface and do not establish new global tokens.

## Creation, simulation, and recovery

- The composer retains the earlier September 13 removal of model and quality controls. Supported controls expose five aspect ratios and one to four images. The pixel hint describes the requested size. The existing request contract, default quality, and saved/reused settings remain unchanged; image details retain their metadata. The public alias does not promise an unverified underlying model.
- Verified account entry precedes the composer. Sign-in returns to the supported Images destination; same-tab, account-scoped drafts survive navigation and recovery when browser storage is available. The former guest-composer behavior is historical.
- Reuse prompt fills the composer and focuses the prompt. Clear, New prompt, and reuse retain a single Undo prompt change opportunity. Reuse creates a fresh image; it does not edit an existing artifact. There are no starter prompts.
- Generate and Cmd/Ctrl+Enter submit settings once per explicit attempt. Pending or ambiguous attempts block a second submission. A retained pending receipt resumes status retrieval after reload without resubmitting generation.
- An active submission or pending receipt occupies the focused canvas with a denoising-style simulation when Image is following the latest result. An explicitly selected earlier image stays visible during another generation; View generation returns to the waiting visual. Grid adds one pending slot per requested image beside previously completed thumbnails. The visible label is **Generation animation**, with copy explaining that the image appears when ready. Accessible placeholder labels also distinguish animation from an image preview. The procedural visual contains no partial result, progress estimate, prompt content, or provider data.
- **Generation options** progressively reveals **Pause updates** or **Resume updates**. It starts collapsed during active work and opens when updates are paused or the attempt is unresolved. Its copy explains that pausing updates does not cancel generation. **Pause animation** remains separate and affects only the visual. Pause updates pauses retrieval and also stops simulation motion; it does not cancel accepted work. Reduced-motion preference keeps the simulation static and hides its animation toggle. Hidden tabs and offscreen canvases suspend animation work; eligible visible canvases resume. Errors stop motion. The bounded rendering and status-retrieval behavior are maintained in [request efficiency](../../docs/maintainers/VERCEL_QUOTA_EFFICIENCY.md).
- A validated completion replaces the simulation with returned image output when Image is following new results. Explicit image selection remains stable through completion. Automatically followed artwork has a brief blur-to-clear reveal on load that is disabled with reduced motion; manual comparison and grid thumbnails do not replay that reveal. Invalid or unsafe outputs never enter the session results. The animation is a waiting treatment, not evidence about the generation process or a global motion rule.
- Status text separates submitting, waiting, creating, interrupted, and complete. Starting again from an unresolved attempt requires acknowledgement that the earlier generation may still finish and another attempt can consume allowance. Rate limits display a countdown when the response supplies a retry interval. Confirmed session rejection links back to sign-in; unavailability retains retry and 403 explains account access. Uncertain results direct the user to check My images. Recovery does not promise exactly-once execution.

## Session results, library, and image detail

Completed images append to an initially empty in-memory array across batches, in completion order, without duplicate receipt/image IDs. **Image** follows the newest completed result by default; **Grid** exposes the bounded recent collection. It retains at most 120 images with a 16 MiB estimated string budget; selected/newest legacy inline records can exceed the budget. Older saved images remain in My images. Both layout and explicit image selection survive switching between Create and the saved library. Presentation changes do not request generation or library data.

Image's 64px filmstrip has a visible selected outline and keeps the selected thumbnail within its scrollable row. Choosing a thumbnail selects the large image without opening the lightbox. Visible previous/next controls and a position such as 2 of 4 browse completed images without wrapping; endpoints disable the unavailable action. Left/right arrow keys work while focus is inside the image stage and leave composer input untouched. **Latest image** clears explicit selection and resumes following new completions. During pending work this action becomes **View generation**. An explicit selection is not displaced by another submission or completion.

Reloading or changing owners resets the session array. Saved My images remains separate, and a restored pending receipt can subsequently add its completed output to the new session. This is not durable result history or a promise of unlimited session memory. The displayed recent count reflects retained completed images; pending slots are distinct. A session note points to My images for saved results.

The selected large image opens the detail lightbox and offers nearby Reuse prompt and download actions. Every Grid thumbnail selects that result and opens the same lightbox, where prompt reuse and download are also available. My images and Favorites retain prompt search, Newest first / Oldest first sorting, refresh, per-page counts, and explicit Previous/Next pagination above and below a single 36-image page. Returning from Create preserves and refreshes that page; Create itself defers library reads. Saved cards offer preview, prompt reuse, favorite, and download. Favorites belong to saved library records. Empty, loading, failed, expired-session, and failed-preview states provide next actions. A same-view refresh failure retains loaded saved images; an authorization failure clears them.

A native modal dialog shows the image beside its prompt, public model name, ratio, quality, and creation time. Its sticky top toolbar keeps the title, previous/next controls, position, and close button available while the dialog scrolls. Opening it captures the currently available source collection, so new generation results or library changes do not reorder the open browsing context. Paging within a session-result lightbox also updates the selected canvas image. The collection contains the current bounded source records and is released on close. Saved cards use 300-character prompt previews and 512-pixel sanitized thumbnails; full prompts load only on inspection or reuse. Detail failure retains the image and provides Retry details, with copy/reuse disabled until full text arrives. Closing/browsing cancels obsolete detail reads.

Left/right arrows page inside the dialog without wrapping. Modified keys, composition, editable fields, and active text selection are excluded. The dialog retains copy, download, reuse, and favorite controls where applicable. Escape, close, backdrop, and Back to studio dismiss it; focus returns to the invoking control if it still exists, with the results area as fallback. Long prompts wrap and scroll in their bounded detail area. Download failure preserves the image and supplies feedback.

## Responsive and accessible behavior

At 760px and below, navigation precedes the composer in both DOM and visual order. The composer initially enters normal flow with full-width aspect-ratio and count groups. Submission folds it to a prompt/ratio/count summary and focuses and scrolls the results area into view, using immediate scrolling when reduced motion is preferred. **Edit prompt** reopens the composer and focuses the prompt. When completed session results exist, **Back to images** folds it again and returns focus to the results without submitting. This return action is mobile-only and stays hidden above 760px. New prompt and reuse reopen it; generation errors also reopen it for correction. My images and Favorites hide the composer so the saved library uses the full viewport width.

On desktop widths above 760px and heights up to 800px, the prompt is shorter and heading/settings/submit spacing is compressed. **Scroll for more settings** cues the independently scrollable controls; Generate stays reachable outside that scroll area. This is a short-screen adaptation, not removal of supported settings.

The results toolbar stacks below 900px. The session Grid retains compact thumbnails on phones with a 100px minimum and 144px maximum column width; the retained pre-ergonomics 390px capture fits two thumbnails per row. Saved library cards now use uniform square frames that contain images without cropping, adaptive desktop columns and two columns at 420px and below; small-screen reuse retains its accessible name while showing an icon. Image detail stacks the preview above its controls. Safe-area padding keeps lower content reachable.

Visible focus rings, labeled native controls, pressed/selected states, text status announcements, modal focus management, and reduced-motion support are implemented. The decorative canvas itself is hidden from assistive technology; its pending wrapper carries the meaningful description. Most primary controls are at least 44px tall. Clear now has a minimum 44×44px hit area while keeping its quiet text-button appearance; the earlier 36px height is historical. Automated accessibility findings apply only to their dated tested states and do not establish a universal target-size or assistive-technology guarantee.
