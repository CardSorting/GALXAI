# Navigation and request intent

<!-- docs-scope: current-guide -->

Private maintainer reference. Public discovery follows [product scope](PRODUCT_SURFACE_STRATEGY.md); search results and local history never grant developer or administrator access. This guide supersedes its earlier unmeasured latency, model, compliance and automatic preloading claims. Dated source history remains in Git.

## Public navigation

The top menu follows a compact social-product order everywhere: Images, Explore, Pricing and Profile, with account actions in a separate fixed-width slot. Profile always points to `/settings?tab=profile`, the authenticated account's private editable profile. The avatar menu and mobile bottom bar use that same destination; they never guess a public handle. Documentation and developer resources remain available through search, the mobile drawer, public reading navigation and footer without competing with the primary creation/discovery loop. The homepage leads with the image experience and keeps concise links to pricing, FAQ and guidance. Active links change color and background without changing their text weight or dimensions. Account loading, guest and signed-in states reserve the same space. Below 1100px the logo/account row sits above a horizontally scrollable, nonwrapping link row; at wider sizes all three regions occupy one row. A focus handler brings clipped links fully into view immediately when the row overflows.

Public Star profiles are nested community destinations under `/profile/<handle>`.
They remain discovery surfaces and are not the destination of the ordinary
account Profile navigation. The shared header and mobile bottom bar keep Explore
selected on those routes. Stream attribution links, the profile breadcrumb
and the full-stream link provide familiar entry and escape paths. Profile galleries preserve the same
newest-first ordering across their initial render and continuation requests. The
profile has authored loading, empty, not-found and recovery states, and its
create action continues into Images without hiding the return path to
discovery. View creations is a native in-page anchor, while Share profile
shares or copies only the canonical public profile URL.

`ProductNavigation` lives above the page loading boundary in the root layout for Home, Images (including Library and Favorites), Sites (including Site detail), public Star profiles and the exact curated public reading routes. These routes share the same mounted header while their content changes. Billing retains the same `Navigation` component in its shared layout; other routes retain it in their page. The compatibility guard suppresses duplicate product headers on legacy error/not-found surfaces. Do not reintroduce page-dependent link lists or a second product header. This preserves the header, not the in-memory image workspace after leaving the Images product.

Pending links use Next.js `useLinkStatus` for a small, dimension-free hint after 120 ms and a text status announcement. The content-area loading placeholder leaves the header available; it never reports internal work or invented timing. Its minimum height is one small viewport (`100svh`), keeping the footer below the first viewport while streamed content arrives. This avoids a visible footer jump when the short loading shell becomes a long page. Navigation uses normal client routing without a page-slide animation. The root reserves scrollbar space, declares its smooth anchor scrolling to Next.js, and disables smooth scrolling and header transitions with reduced motion. Homepage chapter links keep native hashes and `aria-current="location"`; global navigation uses permanent paths and `aria-current="page"`, including a parent link on its guide pages.

`Navigation`, `MobileBottomNav` and `Footer` use `IntentLink`. Links preserve their native href, keyboard focus, open-in-new-tab behavior and Next.js navigation. Rendering a link in the viewport does not prefetch it. A 120 ms hover or focus dwell requests just that destination; leaving or unmounting cancels the timer. Touch navigation works normally without speculative pointer-down work.

Sign-in has its own focused header and legal footer; the shared product footer is omitted there. Workspace links reach a server-verified entry gate. Successful password sign-in uses a fresh document request to avoid stale prefetched anonymous redirects. The exact Images Library/Favorites path and Site/starter destination survive that return; [workspace authentication](operations/workspace-auth.md) owns the contract.

The shared `prefetchOnIntent` helper skips the current route, external URLs, auth/admin/API destinations, hidden/offline pages and browsers reporting Data Saver or 2G. A per-tab budget admits at most three unique destinations in any rolling ten seconds and deduplicates them for thirty seconds. It counts recent admissions directly, so crossing a fixed time-window boundary cannot admit a second burst. These are bounded opportunistic warmups, never guaranteed instant navigation. Authorization remains in middleware and handlers, including private page chunks; there is no middleware exemption for prefetch headers.

## Readable workspace addresses

Create, My images and Favorites use `/images`, `/images/library` and `/images/favorites`. In-studio links use Next.js native history integration to preserve the mounted workspace; Back/Forward derives the selected view and Favorites filter from the pathname. The document title follows that selection. Native links retain keyboard activation, copy-link and modified-click/new-tab behavior. Each address has its own guarded server page for direct entry and reload. Search/sort/page cursors remain local controls; changing a filter resets pagination. Leaving Images or reloading still discards in-memory results while existing account-scoped drafts and durable receipts retain their recovery contract.

Account links use `/login` and `/signup` through the shared safe builder; simple paths remain readable, and nested delimiters are encoded. Existing `/auth/signin`, `/auth/signup` and Images `view` bookmarks migrate via private redirects. No auth routes are prefetched. See [readable URLs](maintainers/readable-urls.md) for exact aliases, tests and rollback. The separate `/library` management dashboard retains its existing bulk-management capabilities.

Billing uses separate Overview, Plan, Credits, Transactions, Invoices and Payment settings paths under one account layout. Its desktop rail becomes wrapping phone navigation; selected transaction filters and pending historical receipt recovery persist across these paths. Pricing and upgrade entry goes directly to Plan, Developer entry goes to `/developers`, and account-credit entry goes directly to Credits. Both search menus expose these six tasks; account-credit intents open Credits, subscription intents open Plan, and card intents open Payment settings. Search does not advertise retired crypto, automatic reload or prepaid-pack setup. API-key tabs and account history use Credits or Transactions as labeled; team history uses Transactions. Old return URLs and section links remain supported through middleware redirects, with the old purchase components removed. The [billing page contract](reference/billing-pages.md) owns the precise state and compatibility rules; no navigation state authorizes a payment.

## Homepage motion and section navigation

The homepage keeps its image-first copy, pricing, example destinations and public-information boundary. `PublicHome` renders the creation story, live community content and Nova attribution on the server. Decorative motion remains bounded and separate from product operations. No animation or visual effect may imply completed generation, payment, access approval or a measured service guarantee.

`useGalaxyInteractions` adds mouse-only depth on devices reporting a fine pointer and hover. The background translates by at most 12px horizontally and 8px vertically, with counter-motion in the orbital layer. Content and controls remain stationary. It ignores touch events, resets on pointer exit, blur and preference changes, and schedules at most one pointer frame at a time. The scroll layer separately translates by at most 72px and scales by at most 6%. “Send a star” starts one 1.1-second decorative shooting star through a native button that works with mouse, touch or keyboard. Repeated activation replaces that effect; no particles accumulate. It is unavailable while motion is off. Pausing, unmounting, hiding the page or scrolling the hero out of view cancels it. There is no audio, generation or published result implied by this optional interaction.

Below the hero, a sticky “On this page” navigation links to Possibilities, Pricing and Questions with native hashes. Its underline and `aria-current="location"` follow the visible section without rewriting browser history. A synchronized pause/resume button keeps motion control within reach without resetting the reading position. Desktop adds the existing Sites destination; mobile retains the three section links and a 44px motion button in one row. Targets and focusable controls leave 84px of scroll space so the bar does not obscure them. The three benefit rows gain a connected track that fills as the reader progresses. The story uses `useStoryEntrance` to connect introductions, benefit rows, the complete plan, FAQ rows and closing action. Each enters once with a short upward movement and a soft deceleration; nearby elements in the same section overlap with 45/65ms spacing, capped at 160ms. Arrivals begin within 48px below the viewport, last 520–760ms and travel 8–18px (25% less on mobile). Their initial opacity stays at 0.76–0.86, and all content is fully visible in default CSS without hydration. Already-visible content at initial setup or resume stays settled. Anchor destinations, focused sections and pointer/click interactions settle immediately, including pending sibling arrivals; fast scrolling past a target cancels its late animation. Reading back does not replay entrances. The existing framework's inline stream-completion script is still required to replace its loading shell; fully disabling JavaScript is not a supported fallback in this pass.

The example picker retains three native pressed buttons and moves a background indicator between them in 280ms. Changing a starter resets the revision. Drafts appear over 360ms with an 18px horizontal movement in the direction of selection; returning to the previous draft reverses direction. A thin amber line and the explicit Revised label reinforce revision state. The live region stays mounted; hidden sizing copies keep all six variants' controls stationary. No automatic example rotation or fake creation progress is introduced. FAQ disclosures keep native `details` behavior with a short opening transition. Press states and arrow movement acknowledge actual interactions.

“Pause motion” is visible above the hero and remembers the visitor's choice for the current tab when session storage is available. Storage failures leave an in-memory choice. Pausing removes local animation and smooth anchor scrolling. Device reduced-motion settings always take precedence and update while the page is open. Reduced motion retains the static galaxy, selected state, section underline and native disclosure feedback. The animation defaults off until preferences are read. Unmount removes the homepage's document-level scroll preference.

Decorative loops stop when the hero leaves the viewport or the document is hidden. The canvas shares the existing motion/visibility state and runs one cancellable animation-frame callback only while enabled and visible. Paints are capped at 30 per second for larger scenes and 24 for scenes below 760px, with 360 or 220 seeded stars respectively. Its backing store is capped near 1.6 million pixels and device scale at 1.5; resizing preserves the scene clock. Pause freezes the current drawing, and resumed motion continues from its accumulated visible time. Initial reduced motion renders a static constellation composition. Missing Canvas 2D support leaves the original image and SVG scene intact. Scroll work separately uses a passive listener and at most one requested frame, with geometry reads before writes. A ResizeObserver updates chapter positions after disclosure or layout changes. IntersectionObserver progressively adds finite arrivals, with a visible fallback when unavailable. The arrival hook retains observation until completion so offscreen cancellation works; hidden documents and cleanup cancel active arrivals. Reading paths and the benefit track ease between scroll samples over 240ms, while closing rings use 300ms. Those short decorative transitions also disappear with pause/reduced motion. Cleanup removes listeners, observers, pending frames and active finite animations. CSS transforms and opacity carry surrounding motion; canvas draws the bounded star formation, and the galaxy's masking is static. These bounds are implementation choices, not claims about field frame rates or Core Web Vitals.

The [scoped design record](../src/components/home/DESIGN.md) owns this homepage's appearance. The patterns adapt [Apple's reduced-motion approach](https://webkit.org/blog/7551/responsive-design-for-motion/), [Material's response timing](https://m1.material.io/motion/duration-easing.html) and [W3C's pause guidance](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html). The playful refinement draws on [Vercel Ship's responsive depth and scroll storytelling](https://vercel.com/blog/designing-and-building-the-vercel-ship-conference-platform), [Vercel's interruptible interaction guidance](https://vercel.com/design/guidelines) and [Linear's predictable action placement](https://linear.app/now/behind-the-latest-design-refresh). These are adaptations of documented patterns, not endorsements, copies of their implementations or performance guarantees.

## Search and keyboard use

The public 404 page uses plain recovery copy, a static icon and Home, Sites, Images, Account and Developer preview links through `IntentLink`. It exposes no diagnostic log, routing explanation or invented service status. Its search helper searches the explicit Images, Sites, developer-preview and account list locally. Up/down selects a result and Enter follows it. Recent visits use the existing bounded local history. It warms only a stable highlighted result through the same budget; it never launches an API data prefetch.

The developer command menu retains its local catalog, typo matching, category filters, clipboard actions and keyboard shortcuts. Its warmup effect runs only while the menu is open, waits 120 ms for the selected result and excludes action-only results. Pointer selections share the global budget. It no longer prefetches the top three alternatives or calls the legacy secondary router path. Audit catalog entries against current product scope before exposing this menu to another audience.

`BroccoliOmniSearch` retains its existing local matching implementation. Its legacy prefetch method is not used by these surfaces. `ResilientClient` and `useResilientQuery` are separate helpers; their caches/retries are not part of the Sites bootstrap or image polling contract. Do not infer a production latency, an authentication guarantee or cross-account cache safety from a helper name or comment.

## Workspace loading and render recovery

Images and Sites (including a nested Site) have route-specific `loading.tsx` and `error.tsx`; public Star profiles have the same authored route recovery without a workspace session gate. The neutral shell follows each workspace's toolbar and composer width on desktop and a single composer on mobile. The client session boundary uses the same shell during profile hydration. One live announcement sits outside the decorative busy region. After six seconds it explains the wait and offers Home; this is a local feedback threshold, not an estimated completion time. Content remains visible by default; a 180ms opacity handoff starts at 0.82, with no translation or delayed controls, and is omitted for reduced motion. The product header remains mounted throughout; navigation feedback continues to use native link pending state. Existing per-tab/account drafts survive navigation; departed editors' in-memory results are not preserved.

`WorkspacePageGate` catches only expected session-verification unavailability before admitting children. Middleware still fails closed, with its separate generic 503 contract. Page-level unavailability can occur after streaming began and therefore can have HTTP 200; rendered recovery is not authenticated workspace access. Unexpected faults reach the product's error boundary. Authored public copy replaces raw root diagnostics. Manual Try again refreshes server state and resets the error boundary in a single transition. A synchronous guard and `aria-disabled` prevent duplicate requests without removing button focus; a polite region announces pending and unsuccessful recovery. Offline retry is unavailable, with a connection message. New recovery content focuses its heading only when focus is otherwise on the document/body container. No timer retries the route render, repeats generation, clears accounts or grants optimistic admission. Session-profile reads have their own finite retry budget.

Browser profile unavailability is contained by `AuthSessionContent` inside the root main-content container. The product header/footer remain mounted; Home, explicitly allowlisted public reading routes, and the exact login/signup entry pages remain available, while private page content stays withheld. The full recovery view offers a destination-preserving sign-in link alongside retry and Home. Its `reauth=1` flag keeps the form visible even when the server still sees an active session; this flag bypasses only an entry-page redirect, never workspace or API authority. A previously verified same-account workspace keeps its mounted editor and input, with a nonblocking connection notice; the wrapper does not remount children when this notice toggles. Retry account in the header and the content retry use the same profile verifier. Pending or failed sign-out also withholds page content, even on public routes. Initial cookie verification starts independently of SDK initialization. Identical checks join the in-flight promise; transient read failures get at most one delayed retry under a shared deadline. Account/token events synchronously fence old checks. Focus/visibility retries use a thirty-second attempt cooldown; actual online recovery and persisted browser-history restoration force a fresh check. A restored document also honors logout markers missed while suspended. Every API retains its authority check. [Workspace authentication](operations/workspace-auth.md) owns these distinctions.

Recovery colors derive from the existing foreground/background theme tokens. Controls wrap, use logical dimensions/borders, and retain focus outlines and forced-color states. The pattern adapts [Carbon's structural skeleton and scoped loading guidance](https://carbondesignsystem.com/patterns/loading-pattern/), [inline action feedback](https://carbondesignsystem.com/components/inline-loading/usage/), [Slack's unfinished-draft continuity](https://slack.com/intl/en-gb/help/articles/201457107-Send-and-read-messages-in-Slack), and [W3C status announcements](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html). GALX's drafts remain best-effort local per-tab/account storage; these references do not imply Slack-equivalent synchronization or measured usability gains.

Run `node scripts/verify-workspace-navigation.mjs` against the isolated compiled server described in [workspace authentication](operations/workspace-auth.md). The fixture injects successful middleware verification followed by a failed page check, and separately injects browser profile failure after server admission. It verifies fresh/manual failed retry, keyboard focus, offline behavior, safe Home, draft continuity, 403, slow feedback, delayed RSC navigation, back/forward, reduced motion, alternate themes, forced colors and doubled text at 320px. It scans response bodies, headers and associated assets. Browser Auth and workspace APIs are synthetic; no production accounts or generation are used. Retain the source build path and completed results; local success does not establish live recovery. If the transition itself regresses, remove its finite CSS handoff while preserving the gates, loading states and explicit refresh recovery.
