# Navigation and request intent

<!-- docs-scope: current-guide -->

Private maintainer reference. Public discovery follows [product scope](PRODUCT_SURFACE_STRATEGY.md); search results and local history never grant developer or administrator access. This guide supersedes its earlier unmeasured latency, model, compliance and automatic preloading claims. Dated source history remains in Git.

## Public navigation

The desktop top menu leads with Explore, Stars, Exhibitions, Collections and Pricing. Signed-in account actions include Private creation, My creations, Account & Usage, Billing & Invoices and Sign out in the avatar menu. Documentation and help remain available through the mobile drawer, public reading navigation and footer without competing with discovery. The homepage leads with published Star work and the promise “No prompting. Just discovery.”; private Image Studio remains behind its authenticated workspace routes. Active links change color and background without changing their text weight or dimensions. Account loading, guest and signed-in states reserve the same space. Below 1100px the logo/account row sits above a horizontally scrollable, nonwrapping link row; at wider sizes all three regions occupy one row. A focus handler brings clipped links fully into view immediately when the row overflows.

On phones, the workspace bottom bar exposes Explore, Library and Search to
visitors; verified signed-in users also get a direct Create shortcut labeled
“Create privately” for the protected workspace. The bar is hidden once the
desktop header navigation is available so tablet users do not get duplicate
navigation. Public reading and exact exhibition/editorial programme routes omit that workspace-only bar.

Public Star profiles are nested discovery destinations under `/profile/<handle>`.
They remain separate from private account management. The shared header keeps Stars selected on those routes; the mobile bottom bar keeps Explore selected. Stream attribution,
profile breadcrumbs and the full-stream link provide entry and escape paths.
Profile galleries preserve consistent ordering across their initial render and
continuation requests and have authored loading, empty, not-found and recovery
states. A published Star Work may offer “Remix privately”; that action leads to
the private workspace and does not change or republish the original. View works
is a native in-page anchor, while Share profile shares only the canonical public
Star URL.

`ProductNavigation` lives above the page loading boundary in the root layout for Home, Explore, Stars, Exhibitions, Collections, private Image Studio, public Star profiles and the exact curated public reading/programme routes. These routes share the same mounted header while their content changes. The desktop primary navigation has no public Create or Library action; signed-in users reach those private routes from the avatar menu. On phones, the bottom bar exposes Explore, Library and Search, plus Create only after browser authentication resolves; Library leads to the authenticated owner-scoped route. `/images` redirects to Explore, while `/images/create`, `/images/library` and `/images/favorites` are separately guarded private workspace routes. The retired Sites workspace paths are gated redirects, not a distinct public product surface. Billing retains the same `Navigation` component in its shared layout; other routes retain it in their page. The compatibility guard suppresses duplicate product headers on legacy error/not-found surfaces. Do not reintroduce page-dependent link lists or a second product header. This preserves the header, not the in-memory image workspace after leaving the product.

Pending links use Next.js `useLinkStatus` for a small, dimension-free hint after 120 ms and a text status announcement. The content-area loading placeholder leaves the header available; it never reports internal work or invented timing. Its minimum height is one small viewport (`100svh`), keeping the footer below the first viewport while streamed content arrives. This avoids a visible footer jump when the short loading shell becomes a long page. Navigation uses normal client routing without a page-slide animation. The root reserves scrollbar space, declares its smooth anchor scrolling to Next.js, and disables smooth scrolling and header transitions with reduced motion. Homepage chapter links keep native hashes and `aria-current="location"`; global navigation uses permanent paths and `aria-current="page"`, including a parent link on its guide pages.

`Navigation`, `MobileBottomNav` and `Footer` use `IntentLink`. Links preserve their native href, keyboard focus, open-in-new-tab behavior and Next.js navigation. Rendering a link in the viewport does not prefetch it. A 120 ms hover or focus dwell requests just that destination; leaving or unmounting cancels the timer. Touch navigation works normally without speculative pointer-down work.

Sign-in has its own focused header and legal footer; the shared product footer is omitted there. Workspace links reach a server-verified entry gate. Successful password sign-in uses a fresh document request to avoid stale prefetched anonymous redirects. The exact Images Library/Favorites path and Site/starter destination survive that return; [workspace authentication](operations/workspace-auth.md) owns the contract.

The shared `prefetchOnIntent` helper skips the current route, external URLs, auth/admin/API destinations, hidden/offline pages and browsers reporting Data Saver or 2G. A per-tab budget admits at most three unique destinations in any rolling ten seconds and deduplicates them for thirty seconds. It counts recent admissions directly, so crossing a fixed time-window boundary cannot admit a second burst. These are bounded opportunistic warmups, never guaranteed instant navigation. Authorization remains in middleware and handlers, including private page chunks; there is no middleware exemption for prefetch headers.

## Readable workspace addresses

Create, My creations and Favorites use `/images/create`, `/images/library` and `/images/favorites`. The legacy `/images` root now redirects to public Explore and is not a Studio alias. In-studio tabs use Next.js native history integration to preserve the mounted workspace; Back/Forward derives the selected view and Favorites filter from the pathname. The document title follows that selection. Native links retain keyboard activation, copy-link and modified-click/new-tab behavior; each private address has its own guarded server page for direct entry and reload. Search/sort/page cursors remain local controls; changing a filter resets pagination. Leaving Images or reloading still discards in-memory results while existing account-scoped drafts and durable receipts retain their recovery contract.

Account links use `/login` and `/signup` through the shared safe builder; simple paths remain readable, and nested delimiters are encoded. Existing `/auth/signin`, `/auth/signup` and Images `view` bookmarks migrate via private redirects. No auth routes are prefetched. See [readable URLs](maintainers/readable-urls.md) for exact aliases, tests and rollback. The separate `/library` management dashboard retains its existing bulk-management capabilities.

Billing uses separate Overview, Plan, Credits, Transactions, Invoices and Payment settings paths under one account layout. Its desktop rail becomes wrapping phone navigation; selected transaction filters and pending historical receipt recovery persist across these paths. Pricing and upgrade entry goes directly to Plan, and account-credit entry goes directly to Credits. Both search menus expose these account tasks; account-credit intents open Credits, subscription intents open Plan, and card intents open Payment settings. Search does not advertise retired crypto, automatic reload, prepaid-pack setup or private access. API-key tabs and account history use Credits or Transactions as labeled; team history uses Transactions. Old return URLs and section links remain supported through middleware redirects, with the old purchase components removed. The [billing page contract](reference/billing-pages.md) owns the precise state and compatibility rules; no navigation state authorizes a payment.

## Homepage motion and section navigation

The homepage keeps discovery as its front door and the capability statement limited to published Star work. `PublicHome` renders the Star spotlight, discovery stream and product story; its first viewport links to `/explore` and `/stars`, not to an anonymous generator. Private creation is described as an authenticated, bounded capability on its dedicated surfaces. Decorative motion remains separate from product operations. No animation or visual effect may imply completed generation, payment, access approval or a measured service guarantee.

Below the hero, a sticky “On this page” navigation links to Releases, About, Discover and FAQ with native hashes. Its underline and `aria-current="location"` follow the visible section without rewriting browser history. A synchronized pause/resume button keeps motion control within reach without resetting the reading position. Desktop and mobile retain these section links; the mobile motion control remains reachable in the same row. Targets and focusable controls leave 84px of scroll space so the bar does not obscure them. The three benefit rows gain a connected track that fills as the reader progresses. The story uses `useStoryEntrance` to connect introductions, benefit rows, the discovery links, FAQ rows and closing action. Each enters once with a short upward movement and a soft deceleration; nearby elements in the same section overlap with 45/65ms spacing, capped at 160ms. Arrivals begin within 48px below the viewport, last 520–760ms and travel 8–18px (25% less on mobile). Their initial opacity stays at 0.76–0.86, and all content is fully visible in default CSS without hydration. Already-visible content at initial setup or resume stays settled. Anchor destinations, focused sections and pointer/click interactions settle immediately, including pending sibling arrivals; fast scrolling past a target cancels its late animation. Reading back does not replay entrances. The existing framework's inline stream-completion script is still required to replace its loading shell; fully disabling JavaScript is not a supported fallback in this pass.

Discover targets `#discover`; the legacy `#pricing` anchor still reaches that
section. The short chapter labels and narrow-screen gaps keep all four links
and the motion control inside a 320px viewport. The discovery section uses
full-row links to Explore, Stars and Collections, with a separate private
creation plans link. It has no public-browsing price table. The targeted local
`scripts/verify-discovery-ui.mjs` fixture verifies completed-feed geometry,
navigation, focus and responsive discovery/pricing behavior.

The public story and examples do not dispatch generation. FAQ disclosures keep native `details` behavior with a short opening transition. Press states and arrow movement acknowledge actual interactions.

“Pause motion” lives in the sticky section navigation and remembers the visitor's choice for the current tab when session storage is available. Storage failures leave an in-memory choice. Pausing removes local story animation and smooth anchor scrolling. Device reduced-motion settings always take precedence and update while the page is open. Reduced motion retains the Star spotlight, section underline and native disclosure feedback. The animation defaults off until preferences are read. Unmount removes the homepage's document-level scroll preference.

The remaining decorative story uses one cancellable animation-frame callback for scroll progress while enabled and visible; it performs geometry reads before writes and uses a `ResizeObserver` to update chapter positions after disclosure or layout changes. `IntersectionObserver` progressively adds finite arrivals with a visible fallback when unavailable. The arrival hook retains observation until completion so offscreen cancellation works; hidden documents and cleanup cancel active arrivals. Reading paths and the benefit track ease between scroll samples over 240ms, while closing rings use 300ms. Those short decorative transitions also disappear with pause/reduced motion. Cleanup removes listeners, observers, pending frames and active finite animations. These bounds are implementation choices, not claims about field frame rates or Core Web Vitals.

The [scoped design record](../src/components/home/DESIGN.md) owns this homepage's appearance. The patterns adapt [Apple's reduced-motion approach](https://webkit.org/blog/7551/responsive-design-for-motion/), [Material's response timing](https://m1.material.io/motion/duration-easing.html) and [W3C's pause guidance](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html). The playful refinement draws on [Vercel Ship's responsive depth and scroll storytelling](https://vercel.com/blog/designing-and-building-the-vercel-ship-conference-platform), [Vercel's interruptible interaction guidance](https://vercel.com/design/guidelines) and [Linear's predictable action placement](https://linear.app/now/behind-the-latest-design-refresh). These are adaptations of documented patterns, not endorsements, copies of their implementations or performance guarantees.

## Search and keyboard use

The public 404 page uses plain recovery copy, a static icon and Home, Explore, private Image Studio, Sites and Account links through `IntentLink`. It exposes no diagnostic log, routing explanation or invented service status. Its search helper searches the explicit product and account list locally. Up/down selects a result and Enter follows it. Recent visits use the existing bounded local history. It warms only a stable highlighted result through the same budget; it never launches an API data prefetch.

The command menu retains its local catalog, typo matching, category filters, clipboard actions and keyboard shortcuts. Opening it moves focus into a modal dialog; Escape, backdrop click and the close control dismiss it and restore the trigger, while Tab remains within the dialog. Search results expose a labelled listbox with one active option, and a no-match state explains what to try next. The account menu uses the same predictable focus return and supports Arrow, Home, End and Escape movement. Its warmup effect runs only while the menu is open, waits 120 ms for the selected result and excludes action-only results. Pointer selections share the global budget. It no longer prefetches the top three alternatives or calls the legacy secondary router path. Audit catalog entries against current product scope before exposing this menu to another audience.

`BroccoliOmniSearch` retains its existing local matching implementation. Its legacy prefetch method is not used by these surfaces. `ResilientClient` and `useResilientQuery` are separate helpers; their caches/retries are not part of the Sites bootstrap or image polling contract. Do not infer a production latency, an authentication guarantee or cross-account cache safety from a helper name or comment.

## Verification and recovery

Run `npm run test:egress:transport` for budget bounds and Sites response/authorization tests. The local Sites and Images browser fixture scripts check desktop/mobile flows; inspect real navigation, request counts and keyboard behavior in a production build. See [quota strategy](maintainers/VERCEL_QUOTA_EFFICIENCY.md) for measurement and limits.

For current public-page acceptance, run `node scripts/verify-public-reading-ui.mjs` after a production build. It checks five viewport widths, the persistent header across reading routes, keyboard navigation, local search and recovery, native disclosures, raw HTTP/RSC metadata, administrator denial, and associated public browser scripts. It uses an isolated server without application credentials.

The older `scripts/verify-navigation-ui.ts` fixture still uses browser-local account setup and needs the verified-session harness before workspace acceptance; its historical results do not establish current workspace entry. Run `scripts/verify-navigation-ui.ts` with the same temporary Playwright/Axe module environment as the [image fixture](maintainers/image-studio-review.md#verification-checkpoint), optionally passing a localhost base URL (default `http://127.0.0.1:3417`). It blocks external requests and mocks account/workspace APIs. It compares header geometry and DOM identity across Home, Sites, Images, back/forward, account states, slow navigation and five viewport widths; it checks dedicated Pricing/FAQ destinations, reduced motion, overflow and scoped header accessibility. Captures and results stay under ignored `.impeccable/review/navigation/`. [September 13 navigation evidence](knowledge/audits/2026-09-13-navigation-continuity.json) records actual checks and limits; browser fixtures are not live acceptance or comprehensive assistive-technology testing.

If prefetch causes a regression, keep native links and disable only warmup scheduling while investigating. Never remove access checks or weaken private cache headers to make a navigation faster. An unavailable prefetched route must still have a normal click/retry path. Public UI wording describes the destination and recovery action, not operational details.

If header continuity regresses, inspect root ownership, the product-route guard, fixed account slots and wrapping before altering routing. Revert the header/root/page-wrapper changes together when necessary; restoring only a page header would create duplicates. Keep the sanitized loading copy and existing access checks. Verify a nested Site and not-found route when changing the product-route predicate.

For homepage changes, run `npm run build`, inspect the rendered production HTML at the root route, and run the targeted detector on `src/components/home/PublicHome.tsx`, `HomeMotion.tsx`, `GalaxyScene.tsx` and `public-home.module.css`. Confirm the first viewport contains one level-one heading, the `/explore` and `/stars` links, the published-Star spotlight (not a private Image Studio composer), no anonymous generation controls or stale showcase labels/asset paths, and no document-width overflow at 320/390/768/1440px. The older `scripts/verify-homepage-ui.mjs` fixture retains historical Sites and galaxy assertions and is not an acceptance gate for this replacement until those assumptions are migrated; do not report its legacy expectations as current behavior. Local HTML and detector results are not live-site acceptance or comprehensive assistive-technology certification.

If homepage motion regresses, first disable the affected enhancement while preserving the server-rendered discovery hero, Star spotlight, discovery links and native story actions. `HomeMotion`, `useStoryEntrance`, the `GalaxyStory` geometry and the scoped CSS can be reverted together without changing product authorization, billing, publication or shared navigation. Do not restore remote showcase images or hidden-by-default content as a fallback.

## Workspace loading and render recovery

Images and Sites (including a nested Site) have route-specific `loading.tsx` and `error.tsx`; public Star profiles have the same authored route recovery without a workspace session gate. The neutral shell follows each workspace's toolbar and composer width on desktop and a single composer on mobile. The client session boundary uses the same shell during profile hydration. One live announcement sits outside the decorative busy region. After six seconds it explains the wait and offers Home; this is a local feedback threshold, not an estimated completion time. Content remains visible by default; a 180ms opacity handoff starts at 0.82, with no translation or delayed controls, and is omitted for reduced motion. The product header remains mounted throughout; navigation feedback continues to use native link pending state. Existing per-tab/account drafts survive navigation; departed editors' in-memory results are not preserved.

`WorkspacePageGate` catches only expected session-verification unavailability before admitting children. Middleware still fails closed, with its separate generic 503 contract. Page-level unavailability can occur after streaming began and therefore can have HTTP 200; rendered recovery is not authenticated workspace access. Unexpected faults reach the product's error boundary. Authored public copy replaces raw root diagnostics. Manual Try again refreshes server state and resets the error boundary in a single transition. A synchronous guard and `aria-disabled` prevent duplicate requests without removing button focus; a polite region announces pending and unsuccessful recovery. Offline retry is unavailable, with a connection message. New recovery content focuses its heading only when focus is otherwise on the document/body container. No timer retries the route render, repeats generation, clears accounts or grants optimistic admission. Session-profile reads have their own finite retry budget.

Browser profile unavailability is contained by `AuthSessionContent` inside the root main-content container. The product header/footer remain mounted; Home, explicitly allowlisted public reading and exhibition/editorial programme routes, and the exact login/signup and Connect entry pages remain available, while private page content stays withheld. The full recovery view offers a destination-preserving sign-in link alongside retry and Home. Its `reauth=1` flag keeps the form visible even when the server still sees an active session; this flag bypasses only an entry-page redirect, never workspace or API authority. A previously verified same-account workspace keeps its mounted editor and input, with a nonblocking connection notice; the wrapper does not remount children when this notice toggles. Retry account in the header and the content retry use the same profile verifier. Pending or failed sign-out also withholds page content, even on public routes. Initial cookie verification starts independently of SDK initialization. Identical checks join the in-flight promise; transient read failures get at most one delayed retry under a shared deadline. Account/token events synchronously fence old checks. Focus/visibility retries use a thirty-second attempt cooldown; actual online recovery and persisted browser-history restoration force a fresh check. A restored document also honors logout markers missed while suspended. Every API retains its authority check. [Workspace authentication](operations/workspace-auth.md) owns these distinctions.

Recovery colors derive from the existing foreground/background theme tokens. Controls wrap, use logical dimensions/borders, and retain focus outlines and forced-color states. The pattern adapts [Carbon's structural skeleton and scoped loading guidance](https://carbondesignsystem.com/patterns/loading-pattern/), [inline action feedback](https://carbondesignsystem.com/components/inline-loading/usage/), [Slack's unfinished-draft continuity](https://slack.com/intl/en-gb/help/articles/201457107-Send-and-read-messages-in-Slack), and [W3C status announcements](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html). GALX's drafts remain best-effort local per-tab/account storage; these references do not imply Slack-equivalent synchronization or measured usability gains.

Run `node scripts/verify-workspace-navigation.mjs` against the isolated compiled server described in [workspace authentication](operations/workspace-auth.md). The fixture injects successful middleware verification followed by a failed page check, and separately injects browser profile failure after server admission. It verifies fresh/manual failed retry, keyboard focus, offline behavior, safe Home, draft continuity, 403, slow feedback, delayed RSC navigation, back/forward, reduced motion, alternate themes, forced colors and doubled text at 320px. It scans response bodies, headers and associated assets. Browser Auth and workspace APIs are synthetic; no production accounts or generation are used. Retain the source build path and completed results; local success does not establish live recovery. If the transition itself regresses, remove its finite CSS handoff while preserving the gates, loading states and explicit refresh recovery.
