# ADR template

<!-- docs-scope: domain-reference -->

Copy to the next unused four-digit ADR path and change the scope to `decision-record`. Register the new path with proposed/not-started metadata before review.

## Context and decision drivers

Describe the concrete problem, affected users/components, constraints and authority boundary.

## Options considered

Describe the plausible alternatives and the tradeoff that determines the choice.

## Decision

State the chosen behavior and scope. Name the owner and acceptance basis. Do not claim deployment from design acceptance.

## Consequences and recovery

Explain benefits, costs, failure/uncertainty behavior, reversibility and compatible rollback. Link a canonical runbook.

## Confirmation and delivery

State how source, tests and actual-client acceptance can confirm the decision. Link dated evidence and practical limits; keep decision status separate from delivery.

## Relationships

Link predecessors, related decisions and current guides. Use reciprocal metadata only for complete supersession; describe partial replacement by topic without retiring unrelated decisions.
