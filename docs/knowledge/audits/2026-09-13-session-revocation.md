# Session replacement and immediate revocation audit

<!-- docs-scope: operational-record -->

Dated September 13, 2026. The [retained local verification](../../../post-mortem/incidents/2026/2026-09-13-workspace-auth/session-revocation-verification.json) covers this working-tree correction. [Current state](../../../post-mortem/CURRENT_STATE.md) owns subsequent release facts. Earlier audit records remain unchanged.

The remaining copied-JWT window is closed at GALX account boundaries through Auth verification followed by an uncached active-session check. The private lookup binds owner and session to verified claims; its public invoker wrapper returns only a boolean. Logout requires the record to be inactive before success. Missing authority is denied; unavailable authority is retryable, without a cached grant. Native persistence now supports the configured PostgreSQL transport and rejects duplicate creation instead of reviving a revoked credential. Team seats use the canonical confirmed account. The internal training guard no longer accepts built-in secrets or editable account metadata.

Old native browser credentials recover through regular account sign-in, with a finite notice and preserved destination. Successful sign-in clears the old alias. Credential strings and matching emails cannot transfer ownership. This uses familiar account recovery and current-browser sign-out semantics. [GitHub documents distinct sessions and revocation](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/viewing-and-managing-your-sessions); that is a UX reference, not a claim about its private implementation. [Supabase specifies the active-session lookup for post-logout JWT rejection](https://supabase.com/docs/guides/auth/sessions#how-to-ensure-an-access-token-jwt-cannot-be-used-after-a-user-signs-out) and [explicit local scope](https://supabase.com/docs/guides/auth/signout). JWT lifetime was not shortened as a substitute for revocation.

Validation passed: 161 regression executions across seven commands, 29 session database checks, the full 94-check isolated database suite, 104 compiled HTTP/asset checks, 15 desktop/phone states, TypeScript, production build and a 637-file compiled boundary scan. Lint has eight existing warnings. The first browser replacement run used an intentionally rejecting password fixture; the corrected full batch passed. The initial full database run found the missing PostgreSQL path and the historical unverified-elevation expectation; both were corrected and the full suite rerun. Evidence retains these failures and scope limits.

The migration preview includes only the additive session lookup. Read-only advisors reported one existing disabled breached-password check. Fresh proof, MFA, full device inventory and device-grant database acceptance remain separate work; legacy elevation stays closed. The [canonical runbook](../../operations/workspace-auth.md) describes rollout, recovery and the limits on in-flight requests and unrelated JWT consumers.

## Production follow-up, September 13

The [migration receipt](../../../post-mortem/incidents/2026/2026-09-13-workspace-auth/session-revocation-migration.json) and [release receipt](../../../post-mortem/incidents/2026/2026-09-13-workspace-auth/session-revocation-release.json) now establish live delivery and bounded account acceptance. The application was deployed from the reviewed working tree; it has no new Git commit or hosted CI result. An isolated real account verified replacement sign-in, local logout, copied-token denial and independent-session refresh; all test accounts were removed. Rendered Images/Sites and 26 linked browser assets passed scoped scans.

Initial live acceptance found a downstream cache override: a four-hour browser TTL changed private headers on static-looking workspace URLs. Authentication still redirected. Cloudflare now [respects existing cache headers](https://developers.cloudflare.com/cache/how-to/edge-browser-cache-ttl/set-browser-ttl/); the [API value is zero](https://developers.cloudflare.com/api/resources/zones/subresources/settings/). Canonical-host private GET/HEAD/prefetch and immutable-asset checks passed after repair. A reusable read-only deployment check and complete runbook/cache guidance preserve this prevention boundary. Page Rules inventory was unavailable to the configured account-owned token; successful observed response checks do not imply a complete inventory audit. Existing browser copies, in-flight work and unrelated JWT consumers remain outside revocation guarantees.
