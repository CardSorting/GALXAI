## Purpose and trigger

Use this runbook to review, enable, diagnose or withdraw a supported application connection. The authority and prerequisites below must hold before activation.

## Authority and prerequisites

GALX Media owns discovery, private media, collections and Star publishing. Connect uses the existing verified account session for application consent and connection management. Nova consumes normalized permission and executes bounded inference. These remain modules with shared existing identity/grant storage. Media and Connect run on Vercel; the accepted persistent Next image runs Nova on the Mac. The placement changes neither the account model nor the execution-side authority.

Identity, inference entitlement, application permission and operational admission are independent. The initial adapter reads `private.galx_inference_access`; only explicit operator grants qualify. Existing Developer Access and Foundry subscriptions are not silently converted. A future approved pass may project eligibility into this record without changing Nova. No price, checkout, wallet, refund, automatic purchase or per-application entitlement is added.

This first release supports reviewed public browser clients and native clients with IP-loopback callbacks, text messages, and optional streaming on `/v1/inference`. A Connect credential cannot become an account session or grant library, billing, publishing, Star or administrator rights.

## Authorization and revocation

Use Authorization Code with S256 PKCE, a registered callback and a Nova resource indicator. Native IP-loopback callbacks may vary only their port. HTTPS callbacks match exactly. Wildcard origins, custom schemes, credentialed CORS and dynamic client registration are not supported. The client identifier is public. The SDK checks issuer and state, removes pending PKCE state before redemption and refuses redirects on credential/inference requests. Its default fetch retains the browser global receiver. Server checks share the canonical-origin policy. Direct deployments retain native Request authority, including exact IP-loopback ports. The Mac bootstrap selects its fixed private listener policy; only exact configured HTTPS application/Connect/Nova hosts qualify, and forwarded metadata cannot select authority. Unexpected hosts/ports fail closed. Authorization query values come from the preserved native URL, so Next normalization cannot turn a registered IP-loopback callback into localhost. Consent mutations still require exact same-origin intent. Account callbacks and redirects use the same canonical URL so cookies and destinations stay together. See [the private listener trust policy](../runbooks/mac-self-hosting.md#request-origin-trust-policy).

Authorization requests last ten minutes. Consent requires the host-only HttpOnly browser cookie and an authenticated same-origin POST. Unknown callbacks never become redirect destinations. Cancel returns `access_denied` to the validated callback. Consent can succeed without entitlement; inference then returns `inference_access_required` while preserving the grant. Re-consent is explicit. Connection management shows only the owner's applications and never tokens.

Codes last one minute and are single use. Opaque access tokens last five minutes. Refresh tokens rotate and have an absolute thirty-day lifetime that rotation never extends. Storage contains hashes only. Code replay with the correct client/verifier, or reuse of a refresh token, revokes the application grant and all its credentials. This conservative policy requires coalesced refreshes. A lost rotation response requires reconnecting, never a retry with a possibly spent token. Storage failure never falls back to a cached grant.

**Revocation window: no grant-cache delay.** Every admission locks and checks the current grant in the primary database. Once disconnect returns success, requests that have not already passed admission cannot run. An admission committed before disconnect may still dispatch or finish. Disconnect is therefore distinct from stopping a task or ending entitlement. An ambiguous disconnect is not acknowledged as successful. Entitlement changes block future admissions without deleting grants or changing media rights.

The SDK holds credentials in private runtime memory; browser session storage contains only pending PKCE state. Browser reload after completion requires reconnecting. Native hosts may add protected OS credential storage. Never expose the runtime, credentials or credential storage to agent context or tool output. A host offering arbitrary code execution must isolate that environment from its credential-owning process and broker only the permitted operation. The reference clients offer no arbitrary-code tool; language instructions alone are not isolation.

The first-party SDK now requests SSE on the wire for both presentation modes. `invoke` without `stream:true` assembles a complete JSON answer locally; explicit streaming returns the incremental response. The client bounds answer content at 2,000,000 bytes, a pending/event frame at 256,000 bytes and the total wire body at 16,000,000 bytes. It validates UTF-8, one consistent request ID, the public model alias, one assistant choice, a supported finish reason and `[DONE]`. Missing, contradictory or excess terminal data becomes `outcome_unconfirmed`; cancellation stops retrieval and never resubmits. Error/admission responses retain their meaningful status. The parser projects an allowlisted result and ignores harmless comment keepalives. No token/provider material enters returned SDK objects.

Nova emits a comment at most once per 15-second quiet read interval after authorized streaming begins. Its wrapper holds at most one upstream read and one timer, respects response backpressure and propagates cancellation. SSE uses private/no-store/no-transform. This preserves the existing 300-second deadline and registered terminal persistence. Raw HTTP JSON remains supported, but long complete-answer transport through an idle-limited edge should use the SDK's streamed wire mode. No polling, durable retrieval or automatic resume is added.

The [Mac self-hosting procedure](../runbooks/mac-self-hosting.md) packages the complete Next server, rather than extracting a new Nova service. The accepted origin-corrected image supersedes the earlier incompatible self-host artifact and is reused unchanged for the controlled live transition. Its loopback-only default, non-root/read-only policy, private configuration, bounded caches/logs, immutable archive and 480-second stop grace remain mandatory. Package presence alone is not existing-account or public-path acceptance.

## Admission, output and uncertainty

Nova uses a normalized permission interface, without gallery, checkout or client-specific commercial logic. An account shares two active slots and twelve admissions per minute across its applications; the deployment has sixty-four active slots. Existing execution-side admission remains authoritative. These safeguards do not create customer token balances. A six-minute reservation exceeds the five-minute execution deadline; unknown/cancelled requests retain their slot until its deadline.

Every request requires an idempotency key. Duplicate IDs, including changed content under the same key, never dispatch again. IDs remain for at least thirty days. The SDK submits inference once, without retrying busy, cancelled or uncertain work. `service_busy` with `not_accepted` preserves known non-admission; `outcome_unconfirmed` retains consequential uncertainty. There is no status/result retrieval in this first contract. Retain delivered output; starting new work after uncertainty requires a deliberate application/user decision.

JSON and SSE are rebuilt with explicit allowlists. The public alias `galx-nova` promises no underlying model. Upstream IDs, models, headers, usage objects and reasoning/diagnostic metadata are excluded. The execution adapter requests the original stream for both client response modes; JSON aggregation does not inherit the legacy adapter’s default finish reason. SSE requires an allowed finish reason followed by a final completion marker; truncation produces an unknown-outcome error without a success marker. Cancellation propagates and stops retrieval but does not promise upstream cancellation. Request records retain hashes and state, not prompt/output content. The host holds a registered terminal-lifecycle promise through the existing database write. Disconnect and deadline notification also finalize after response handoff, without depending on a stream-cancel callback. Concurrent terminal calls share one write, including its ambiguous failure. Once interruption has claimed `unknown`, buffered completion cannot report success. The host budget is finite and does not guarantee persistence after an infrastructure failure.

## Procedure

1. Establish target lifetime and placement before releasing a candidate. Nova registers terminal work with Next `after()` before admission and retains its 300-second execution deadline. Its Mac container has a 480-second shutdown grace. Vercel runs only the short Connect endpoints and Media; the inference route is absent from that release, and retired legacy paths fail closed. Use [Mac operation](../runbooks/mac-self-hosting.md), [web packaging](../VERCEL_DEPLOYMENT.md#canonical-clean-hosted-package) and the [transition runbook](../runbooks/nova-hosting-transition.md). The accepted image's whole-image synthetic checks and the October 3 real-provider transition are distinct evidence. A changed image, authority configuration or ingress must revalidate the affected Connect, admission, lifecycle, origin and public-boundary checks before activation. Do not shorten the execution deadline, reopen Vercel execution or infer authorization from a healthy process.
2. Inspect current migration state before any release. The primary already contained `20261003131619_galx_connect_grants`. The authorized transition applied only the reviewed `20261003202702_relay_refill_integer_credit` after a successful rollback-only dry run; it preserves exact fractional credit and adds no entitlement semantics. `20260926081213_orbit_public_identity` remains pending. Do not reapply Connect or automatically apply unrelated pending migrations. Full-chain disposable fixtures are separate evidence.
3. The active server-only configuration is `GALX_CONNECT_ORIGIN=https://galx.ai` and `GALX_NOVA_RESOURCE=https://nova.galx.ai`. Other separately validated deployments may share a single HTTPS origin. IP-loopback HTTP is allowed for isolated local work. Handlers verify their configured origin; a host change requires corresponding registration/client configuration.
4. Set `GALX_CONNECT_CLIENTS` to reviewed entries with `id`, `name`, `kind`, `redirectUris`, and `origins`. The browser reference uses ID `reference-browser`, callback `http://127.0.0.1:4400/callback` and origin `http://127.0.0.1:4400`. The native reference uses ID `reference-native`, callback `http://127.0.0.1/callback` and no browser origins. These two first-party registrations were reviewed for the controlled transition; only explicit eligible accounts can admit inference. Additional clients/origins require a separate release decision.
5. Grant a verified existing test account bounded entitlement with `node --env-file-if-exists=.env.local --import tsx scripts/manage-connect.ts grant <account-uuid> <ISO-expiry>`. This trusted server CLI is not an end-user endpoint. `end-access <account-uuid>` withdraws entitlement independently. Neither operation purchases anything.
6. Set `GALX_CONNECT_ENABLED=1` only for the reviewed target. Run `node --import tsx examples/connect/native.ts` or `node --import tsx examples/connect/browser/serve.ts`, with matching origin variables. The browser server serves static content and never proxies inference or holds provider credentials.
7. Verify actual inference readiness and the authenticated model contract separately from process liveness. If provider sign-in is expired or rejected, use the existing [manual provider reconnect procedure](../maintainers/RELAY_CREDENTIAL_ENROLLMENT.md#refresh-an-existing-account) in the matching desktop; a GALX login or inference entitlement does not renew provider authority. A retained failure count does not itself prove that saving a replacement failed. Reconcile the saved credential and run one bounded, independently identified acceptance request when current access permits it. Do not substitute keys, reset counters, reopen ingestion, reset ownership or replay an ambiguous attempt.
8. Verify real account sign-in, consent, result delivery, stopping, revocation, expiry and unavailable capacity. Confirm unchanged library/publishing/Star rights. Retain HTTP/stream/header observations through allowlisted private evidence, along with browser and native client outcomes. Record hosted evidence separately before advertising availability.

## Stop conditions

Do not activate after failures in callback/CORS isolation, current-grant checks, admission, uncertainty handling, target request-lifetime handling or response scans. Leave the feature disabled while its database, registrations or execution capability are unavailable. Enabling disconnect notification without protecting terminal persistence is not a safe transport correction. A hosting plan with a longer duration does not itself add the missing cancellation cleanup registration. The enable flag is not deployment evidence.

## Recovery and rollback

Hosting rollback preserves the primary grant, token, entitlement, quota and execution tables. Deny Nova ingress/admission, retain uncertain work, and restore a compatible Mac package/configuration under the [transition procedure](../runbooks/nova-hosting-transition.md#recovery-and-rollback). Vercel is not an inference fallback. Shared GALX identity and Media remain operational independently.

The [Connect DOWN migration](../../supabase/rollbacks/20261003131619_galx_connect_grants.down.sql) is destructive feature removal, not a hosting rollback. It drops six private tables and invalidates credentials; it needs a separate explicit decision and retained evidence. Never use it to recover a container, route or provider outage.

When an approved maintenance schedule invokes it, `scripts/manage-connect.ts cleanup` performs bounded cleanup; the transition did not install a new Vercel or Mac scheduler. Each run deletes at most 1,000 expired records per table, retaining refresh-reuse evidence beyond the absolute lifetime and request IDs for thirty days. Grant history remains. The new foreign keys specify cascades when an auth account is deleted. The existing canonical identity guard currently rejects direct auth-user deletion, as the complete-chain fixture confirms. This is not an account-erasure implementation; revoke connections and withdraw entitlement independently when containing access. Monitor backlog privately; this change does not provision a scheduler.

## Verification and evidence

Run `npm run test:connect`, `npm run test:connect:db`, `npm run db:verify`, the account/media regressions and a production build. The [initial local review](../../post-mortem/releases/2026-10-03-connect-local-review.json) records synthetic protocol, HTTP, full-chain PostgreSQL and browser scope. The [first real attempt](../../post-mortem/releases/2026-10-03-connect-real-acceptance.json) preserves actual Google sign-in, consent/PKCE, entitlement, expiry, refresh, revocation and the initial provider-expiry blocker. The [resumed acceptance](../../post-mortem/releases/2026-10-03-connect-provider-recovery.json) adds two real provider completions, independent-client continuity, real SSE, shared-capacity rejection, a client deadline, explicit cancellation and disconnect during streaming. Subsequent admissions were denied within observed round trips of 167–175 ms after acknowledgement; the design remains no grant-cache delay, not a timing SLA.

The subsequent [neutral-outcome correction](../../post-mortem/releases/2026-10-03-neutral-outcomes.json) separates provider evidence from execution uncertainty in the installed runtime. Interrupted work remains `unknown` and non-replayable while settling without a provider failure observation. Account availability defaults to unknown; saved sign-in and retained failure warnings do not imply a live health verdict or block reconnect. This changes neither Connect consent nor current-grant revocation.

The one-second client deadline left Nova `unknown` even though the original provider attempt later completed. The cancelled stream remained `unknown` in both records. Neither was replayed. This does not establish every provider terminal condition: the longer executor first-output, idle and wall deadlines were not forced. All six historical cohort grants were revoked and the temporary entitlement disabled at acceptance close; completed/unknown request history is retained. [ACT-039](../../post-mortem/incidents/2026/2026-10-03-connect-acceptance/README.md) records the bounded acceptance completion. Inspect rendered screens and compiled public assets for each release; local acceptance does not establish hosted readiness or continuous availability. ACT-001 subsequently closed target inventory, and ACT-044/045/046 hold hosted artifact, transport and configuration readiness. Earlier public-release warnings retain their separate classifications and deadlines.

The initial hosted enablement fixture used the then-unchanged Nova source in isolated Linux Node 22 with synthetic storage and no network. Completion persisted `completed`; surviving-process cancellation persisted `unknown`; modeled serverless reclamation left a retained `running` admission. This was not a live production failure. The later registered-terminal adaptation and Mac origin correction have their own dated evidence; neither erased that counterexample.

The [October 3 transition](../../post-mortem/releases/2026-10-03-nova-mac-transition.json) then exercised the actual existing account, GALX consent/PKCE, controlled Mac ingress and provider. Four deliberately bounded upstream attempts total produced two completions and two neutral terminal `unknown` interruptions across pre-cutover and final-hostname checks. Duplicates produced no further attempts. Revocation denial measured 313 ms on the acceptance hostname and 252 ms on `nova.galx.ai`, after acknowledgement; refresh could not restore either grant. These are observations, not latency SLAs. Both acceptance connections are revoked; the single bounded entitlement expires independently. Recovery reloaded the verified image and preserved completed/unknown records and revoked authority. The controlled five-minute observation passed. ACT-047 records this transition separately from the already-closed ACT-044/045/046 candidate gates; public-release and host availability gates remain separate.

## Standards and limits

The wire contract follows [OAuth authorization code](https://www.rfc-editor.org/rfc/rfc6749.html), [native applications](https://www.rfc-editor.org/rfc/rfc8252.html), [security best practice](https://www.rfc-editor.org/rfc/rfc9700.html), [resource indicators](https://www.rfc-editor.org/rfc/rfc8707.html), and [revocation](https://www.rfc-editor.org/rfc/rfc7009.html). It has no third-party conformance certification. Supabase's current OAuth server lacks custom scopes; its default authenticated audience would also need broader policy isolation. Connect therefore reuses verified account identity without enabling broader third-party account tokens or reviving provider-ingestion routes.
