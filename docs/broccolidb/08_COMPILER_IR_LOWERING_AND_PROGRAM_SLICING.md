## 1. Context & The Compiler Analogy

Modern software compilers (such as LLVM, GCC, and Rust `rustc`) do not treat source code as flat character arrays. Instead, they parse source text into an **Abstract Syntax Tree (AST)**, lower it into a **Control Flow Graph (CFG)** in **Static Single Assignment (SSA)** form, apply rigorous optimization passes (Dead Code Elimination, Constant Propagation, Loop Invariant Code Motion), and emit target machine code.

```
[ Traditional Compiler Pipeline (LLVM) ]
  Source Code ──► AST ──► LLVM IR (SSA) ──► DCE & LICM Passes ──► Machine Code

[ BroccoliDB Representation Pipeline (GALXAI) ]
  Raw Context ──► AST ──► Invariant DAG ──► Institutional Pruning ──► Compacted Context C'
```

BroccoliDB applies this exact compiler engineering discipline to Large Language Model prompt contexts:
* **The Environment**: The raw repository, ADRs, RFCs, and runtime configs represent the unoptimized program AST.
* **The Intermediate Representation (IR)**: The normalized AST generated by the 180 domain-specific compactors.
* **The Lowering & Optimization Pass**: The `BroccoliCompactionFacade` acting as the compiler optimization driver.
* **The Target Machine**: The downstream inference model $\mathcal{M}$ receiving the minimal task-sufficient representation.

## 2. Static Single Assignment (SSA) for Context Invariants

In LLVM SSA form, every variable is assigned exactly once, and every use is dominated by its definition. 

In enterprise prompt contexts, institutional entropy creates **Multiple Contradictory Assignments** over time:
```text
(2022) var JWT_AUTH = "HS256"      [ADR 0012]
(2024) var JWT_AUTH = "RS256_v1"   [ADR 0028]
(2026) var JWT_AUTH = "RS256_v2"   [Active Invariant]
```

When an LLM parses this uncurated history, self-attention suffers from **Reaching Definition Ambiguity** ($\phi$-node confusion).

```
                      [ Reaching Definition Ambiguity ]
                      
                                ADR 0012: HS256
                                       │
                                ADR 0028: RS256_v1
                                       │
                                2026 Invariant: RS256_v2
                                       │
                                       ▼
                       LLM Attention Confusion (Softmax Dilution)
```

BroccoliDB constructs a **Temporal Invariant Dominator Tree**:
1. It analyzes deprecation headers and version tags.
2. It detects that ADR 0045 strictly dominates ADR 0012 and ADR 0028.
3. It performs **Dead Store Elimination (DSE)** on superseded directives, resolving all $\phi$-nodes to the unique authoritative 2026 invariant.

## 3. Weiser's Program Slicing Applied to Software Contexts

In 1984, Mark Weiser introduced **Program Slicing**: an algorithm that extracts the minimal subset of program statements that directly or indirectly affect a given variable at a specific execution point (the *slicing criterion* $\langle p, V \rangle$).

BroccoliDB generalizes Weiser's backward slicing to prompt contexts:

### Definition 3.1 (The Prompt Slicing Criterion)
Let $\tau \in \mathcal{T}$ be the agent task (e.g. `ImplementEdgeRouteHandler`), and let $\mathcal{I}_{\tau}$ be the set of mandatory invariant symbols (e.g. `runtime = "edge"`, `zeroizeBuffer()`, `RS256`).

The slicing criterion is:

$$\mathcal{S}_{\tau} = \langle \text{ActionPoint}, \, \mathcal{I}_{\tau} \rangle$$

### The Slicing Algorithm:
1. **Symbol Dependency Graph (SDG)**: Construct the directed graph $G = (V, E)$ where nodes represent prompt statements and edges represent data or control dependencies.
2. **Backward Reachability Traversal**: Compute the set of ancestor nodes in $G$ from which $\mathcal{I}_{\tau}$ is reachable:
   $$\text{Slice}(\mathcal{S}_{\tau}) = \{ v \in V \mid v \rightsquigarrow \mathcal{I}_{\tau} \}$$
3. **Dead Context Pruning**: Any node $u \in V$ with no directed path to $\mathcal{I}_{\tau}$ (such as RFC Form 42-B or historical committee meeting minutes) has reachability distance $\infty$ and is pruned.

```
                      Symbol Dependency Graph (SDG)
                      
   [ RFC Form 42-B ]              [ 2026 Active Invariants ]
     (Unreachable)                            │
          │                                   ▼
          │                            [ RS256 Key v2 ]
          │                                   │
          ▼                                   ▼
     (PRUNED: 0%)                  [ Target Action Point A ]
                                        (PRESERVED: 100%)
```

## 4. Invariant Hoisting (Loop Invariant Code Motion Analogy)

In standard compiler optimization, **Loop Invariant Code Motion (LICM)** hoists invariant computations out of hot inner loops to the loop preheader, reducing execution frequency from $\mathcal{O}(N)$ to $\mathcal{O}(1)$.

BroccoliDB performs **Prompt Invariant Hoisting**:
* In multi-turn agent dialogues or mega-incident logs, critical runtime constraints are often buried in deep conversation turns or noisy stack traces (the "Lost in the Middle" trap).
* The `BroccoliDynamicInvariantHoistBuffer` identifies invariant AST tokens and hoists them to the **Canonical Header** of the prompt payload before dispatching to the inference wire.
