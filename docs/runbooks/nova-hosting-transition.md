# Nova hosting transition and retirement

<!-- docs-scope: current-guide -->

Private release-operator runbook. [Current state](../../post-mortem/CURRENT_STATE.md) and the [October 3 transition record](../../post-mortem/releases/2026-10-03-nova-mac-transition.json) own observed deployment evidence. [ADR 0167](../adr/0167-nova-mac-runtime-placement.md) owns the accepted placement decision. This procedure does not authorize a new rollout or public launch.

## Purpose and trigger

Use for an explicitly authorized Nova runtime replacement, ingress change or recovery. Since October 17, canonical web/Media/Connect also run on the Mac under a separate whole-web profile against native central/Auth; Nova retains narrow authority and its exact resource route. Use [account migration](local-account-migration.md) for that completed source-copy/guard/whole-web switch and [current evidence](../../post-mortem/releases/2026-10-17-central-native-cutover.json) for account corrections. There is no Vercel inference fallback or dual primary. Moving an origin never migrates an execution by replaying it.

## Authority and prerequisites

Capture the actual serving web release, aliases, DNS/tunnel versions, configuration names, client callbacks, database migration state, running requests and rollback artifacts before mutation. Keep secret values in private runtime configuration, never in release evidence. Confirm which settings are shared by Media, Connect and existing image/Sites workloads before removal.

Require a hash-verified Mac image/archive with a matching whole-image receipt under [Mac operation](mac-self-hosting.md), the reviewed explicit Nova configuration, current monitor ownership evidence and a clean Media/Connect package under [web deployment](../VERCEL_DEPLOYMENT.md#canonical-clean-hosted-package). The October 3 transition reused the accepted image unchanged. A new image is a new candidate requiring reacceptance.

The owner's workstation must remain usable. Follow [non-disruptive resilience acceptance](mac-self-hosting.md#non-disruptive-resilience-acceptance): do not reboot/shut down/sleep/log out the Mac, disrupt host networking, pressure host storage, restart unrelated shared services or change global power settings. Test owned service replicas and isolated recovery instead. Physical-host drills are **UNVERIFIED — DEFERRED BY OPERATOR**; a provisional normal-reboot startup assumption is not acceptance evidence.

Use only existing accounts, reviewed first-party clients and explicit bounded entitlement. Account sign-in and application consent alone do not authorize compute. Keep scope `inference:invoke`, audience `https://nova.galx.ai`, issuer `https://galx.ai`, exact registered callbacks, S256 PKCE and current-grant checks. Ordinary accounts remain ineligible. No automatic grants, enrollment, purchasing or public discovery is added.

## Procedure

1. **Stage privately.** Verify archive/whole-image acceptance. Current native placement uses `plan-nova-native`, its own owner-only narrow configuration and default loopback 17789. The prior hosted-compatible project/17787 is retained stopped. Use stage/status; non-root/read-only execution, resource bounds and 480-second shutdown remain mandatory. Never expose database or provider control ports.
2. **Prepare exact ingress.** The accepted Cloudflare Tunnel rule matches hostname `nova.galx.ai` and path `^/(v1/inference|\.well-known/oauth-protected-resource)$`, forwarding to the existing Docker host loopback entrance. Set the exact canonical `httpHostHeader`; keep chunked streaming enabled. Preserve other Media/image tunnel rules and the final deny rule. No wildcard Nova route, buffering proxy, request replay, provider header forwarding or public health/control endpoint is permitted. TLS terminates at the existing controlled edge. Nova retains its own authentication, body limits, capacity and 300-second execution deadline.
3. **Prove the replacement before changing DNS.** Use a temporary exact acceptance hostname with the same origin policy and one existing eligible account. Complete real consent/PKCE and one minimal real streamed inference. Require valid terminal completion and persisted provider/Nova evidence. If safe, cancel one bounded request after its first delta. It must stay neutral/unknown with no provider failure increment or automatic replay. A deliberate duplicate must refer to the original record, never another provider attempt.
4. **Prove revocation and recovery.** Revoke the grant, observe acknowledgement and denial on the next admission; refresh must fail. Record elapsed time as an observation, never an SLA. Stop cleanly with no active work, load the verified archive, resume the exact image, restart the monitor where safe and verify private ownership and sanitized browser status. Confirm completed/unknown records, revoked grants and exact persisted quota survive. A new consent after recovery proves shared account authorization still works. Do not restart unrelated host services solely for a drill.
5. **Keep old admission closed.** The October 3 transition installed the Media/Connect-only Vercel artifact and project-wide legacy inference deny rule. They remain historical containment, not a native-database fallback. Verify old text/run/embedding/queue paths stay denied across retained Vercel releases. Confirm active Nova work/leases have drained before replacement; preserve unknown records without transfer or replay.
6. **Cut only the approved responsibility.** For a Nova-only change retain before/intent records and modify its exact route only; preserve the separately active canonical web route, www redirect, storage, account/Connect and provider ownership. The broader October 17 switch has its separate account-migration operator/receipt; do not repeat it or restore its stale source while changing Nova.
7. **Accept on the final hostname.** Repeat the smallest real completion/interruption pair only if required to prove this final path. Check duplicate denial, bounded capacity rejection, current-grant revocation and refresh denial, private monitor ownership and sanitized browser results. The October 3 pass used four upstream attempts total across pilot and final path. It did not load-test capacity or force a real provider failure/deadline.
8. **Observe before retirement.** The transition used a minimum 300-second window, 21 observations over 313 seconds: Nova discovery, unauthorized inference denial and private ownership freshness. The observer retained an automatic deny-only route rollback for failed authorization/private-control checks or three consecutive liveness failures. That bounded observer finishes; it is not ongoing monitoring. Retain normal private service supervision after it exits.
9. **Preserve retirement and recovery sources.** Nova's Vercel domain/alias were retired in the October 3 scope. Keep historical releases denied; do not repeat old deletion. The October 17 canonical web move preserves www's redirect and the external production configuration used for vault-seed recovery. Remove an obsolete secret/schedule only after current inventory proves its exact scope and replacement recovery path. Never discard shared key recovery merely because serving moved.
10. **Verify and close.** Remove the temporary acceptance hostname/rule. Verify Nova's exact route, unauthenticated/revoked denial, private-path 404, old web inference denial, Media/Connect pages and rendered browser assets. Retain source/image/archive/deployment hashes, sanitized observations, terminal records, migration receipt, recovery and limitations. Close the transition action only after these checks pass. Stop; public/commercial activation is separate.

The Vercel deny rule matches `^/(v1/(inference|chat/completions|completions|messages|embeddings)/?$|api/(chat|generate|run)/?$|api/queues(/.*)?$)`. It is independent of source deployment hooks, so restoring an old Media release cannot silently restore Nova. The application guard is also enforced before route dispatch. Existing media image APIs and stored chat-history CRUD are intentionally retained.

## Stop conditions

Stop/contain on authorization bypass, wrong cohort admission, exposed credentials or private ownership evidence, revoked access admitted after acknowledged revocation, duplicate upstream execution, automatic replay, corrupted state, neutral events adding provider failures, broken normal streaming, persistent failure to admit valid work or lost monitor/control evidence. Ordinary provider unavailability or an honest terminal `unknown` alone is not a rollback trigger.

An uncertain management API acknowledgement requires a read-only state reconciliation before another mutation. A DELETE can succeed with an empty body. Compare route objects semantically; a provider reordering JSON properties is not drift. Never rerun a destructive step merely because a diagnostic parser failed.

## Recovery and rollback

First close the affected Nova ingress/admission without changing shared GALX identity or Media. Preserve all execution and grant records. Drain within the accepted shutdown allowance, restore a verified compatible Mac image/configuration and prove the private boundary before re-enabling the route. Do not restart ambiguous work. The verified archive and live primary/execution databases reconstruct Nova independently of Vercel.

During a reviewed observation window, a retained prior target may be used only as deny-only containment, never Vercel inference fallback. After domain retirement use the tunnel deny rule; reopening inference or weakening its firewall is prohibited. Media recovery now needs a native-compatible image and current data; its old Vercel/source snapshot is not a safe writer fallback.

Keep the additive Connect and integer-refill schemas during hosting rollback. Existing service versions remain compatible with nullable integer credit columns; no old execution row was backfilled. Do not apply destructive DOWN migrations or reset fractional credit. Monitor recovery uses the existing private ownership path, never browser-visible installation evidence.

The Mac remains a single failure domain. A local verified archive does not cover hardware loss. Physical reboot/power loss, sleep/wake/closed lid, logout and disruptive shared-daemon/network drills are **UNVERIFIED — DEFERRED BY OPERATOR**. Independent restoration of the complete application package/VM/queues/secrets remains unverified; the separately verified native database off-device recovery does not establish that broader scope. Documented startup after normal reboot may be assumed provisionally for continued controlled development, without treating it as a pass or a production-readiness guarantee. Do not disable FileVault or change global power policy to conceal those limits. Stop after safe service-level evidence is complete.
