# Maintainer learning path

<!-- docs-scope: current-guide -->

Progress by demonstrated outcomes, at a pace appropriate to the maintainer. This path grants no repository role, production access or certification. Begin with [your first safe change](../tutorials/first-change.md).

| Stage | Exercise | Evidence of readiness |
| --- | --- | --- |
| Orient | Read product scope, current state, documentation policy and the owning domain | Explain public product access, private developer approval and the difference between source and deployment |
| Trace | Follow one image or Sites operation from authorized entry to durable outcome | Identify identity, ownership, acknowledgement and uncertain-outcome boundaries using source links |
| Change | Make a bounded fix with the affected guide and appropriate tests | A reviewer can assess the problem, final behavior and validation from the diff |
| Recover | Walk an incident runbook using a disposable fixture or recorded scenario | State stop conditions, original-operation recovery and the acceptance evidence needed |
| Decide | Review a relevant ADR; create one only for a consequential new choice | Alternatives, consequences, scope and confirmation are explicit |
| Maintain | Run source impact, review status and docs checks | Explain stale vs due vs unreviewed without stamping unknown material fresh |

Use [domain checks](../knowledge/DOMAINS.md) for the chosen exercise. Read test prerequisites and use isolated fixtures. A routine onboarding exercise does not require production migrations, paid provider benchmarks, publishing, external messages or credential discovery.

Before operational work, confirm actual authorization and the component's recovery procedure. A calendar milestone or completed checklist cannot substitute for those conditions. Record learning gaps in the review/PR context and revisit the relevant guide.
