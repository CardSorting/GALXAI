# Assess maintainer readiness

<!-- docs-scope: current-guide -->

Use a concrete change and an isolated recovery scenario to assess readiness for the intended responsibility. Follow the [learning path](DAY_1_TO_30_ONBOARDING_ROADMAP.md); this assessment does not grant access or certify a maintainer automatically.

| Capability | Demonstration |
| --- | --- |
| Locate authority | Find the owning source, current guide, decision and dated deployment evidence |
| Respect product boundaries | Explain public Images/Sites access, private developer approval and staff authorization |
| Preserve ownership | Trace the authenticated principal and an owned resource through the relevant request |
| Handle uncertainty | Recover the original operation without inventing completion or automatically dispatching a duplicate |
| Verify a change | Choose relevant tests, preserve fixtures and report what was not exercised |
| Maintain knowledge | Reconcile full guide bodies, distinguish review states and update an incident or ADR when warranted |
| Release safely | Identify target, dependencies, stop conditions, compatible rollback and actual-client acceptance |

The reviewer records the exercised scenario, date, evidence and remaining gaps. Use actual reviewer identity when available; do not invent a team or on-call assignment. Access changes require their own authorized administrative path. Reassess the affected capability when ownership or architecture changes.
