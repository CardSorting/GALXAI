| Sub-token scope/lifetime escalation | Requested scopes are bounded by parent and expiry; sub-tokens cannot manage account sessions | Native credentials are a separate contract from Supabase browser sessions |
| Auth or database outage becomes authorization | Generic unavailable response; authoritative native creation/lookup/rotation/revocation and device-grant results; no cache grant after denial/outage | Active-session and native persistence have isolated database tests; device-grant RPC routes still use mocks |

| Callback substitution, CSRF or authorization-code interception | Reviewed exact redirects/origins, S256 PKCE, state/issuer checks, browser-bound consent and same-origin decision | Native callbacks permit only IP-loopback port variation; no custom schemes or wildcard registration |
| Disconnected application continues new admissions | Durable current-grant check serialized with disconnect; rotating refresh tokens and reuse revocation | Already-admitted work may finish; ambiguous disconnect is not success |

## Authority and custody

Auth-service verification plus a live owner-bound session check proves current application account authority. Developer approval, resource ownership, subscription entitlement and staff membership are independent checks. A public API key or editable user metadata cannot confer staff rights. Browser cookies and in-memory SDK sessions remain credentials/candidates to verify; they are not trusted merely because they exist. Native credential verification checks cryptography, signed account provenance, expiry, revocation and database ownership.

Provider credentials require manual sign-in and explicit scoped review/registration in the fixed Premium monitor. Only the central project manages accounts, assignments, lifecycle and the existing account lease ledger; the execution project cannot administer accounts. Viewer, operator, registrar and runtime principals have distinct scopes. Legacy enrollment applies only to eligible unassigned controller accounts. Removed accounts remain revoked with retained evidence, and connection loss remains unknown health. See [the full account contract](reference/relay-account-management.md). Application provider ingestion and automatic provider-session renewal are closed under [the ingestion reference](STANDARDIZED_OAUTH_AND_INGESTION_ARCHITECTURE.md). Stored operational records retain their protocol identifiers privately. No user-facing security grade, certification badge, universal deletion guarantee, hardware isolation guarantee or verified model identity is inferred from internal class names.

[Connect operations](operations/galx-connect.md) owns the protocol, reviewed client registration, resource scope, fail-closed storage behavior, shared capacity and separate entitlement adapter. The text output contract rebuilds JSON and SSE fields and does not forward upstream headers, model identities or diagnostic metadata. Unknown outcomes never replay automatically. Local protocol, raw HTTP, disposable database and intercepted browser fixtures exercise these boundaries. The October 3 real-account acceptance also verifies consent, PKCE, expiry, refresh and grant revocation in a local production-build environment using the existing account database. The [resumed acceptance](../post-mortem/releases/2026-10-03-connect-provider-recovery.json) additionally verifies real provider completion, independent-client continuity, shared capacity, client-deadline uncertainty, cancellation and revocation during streaming. Credential values remained server/runtime-owned. Hosted application activation remains unverified; the Mac candidate separately exercises the full executor deadline with a controlled provider under its dated correction record; the [earlier blocked attempt](../post-mortem/releases/2026-10-03-connect-real-acceptance.json) remains dated evidence.

## Residual risks and acceptance

Default browser sign-out targets the current session and confirms that the session record is no longer active before success. Account entry, profile, team seats and shared API identity all require the same uncached check. A copied JWT is denied on subsequent GALX account requests even while its signature/expiry remain valid. Other sessions stay active; no lifetime setting or global revocation is changed. A future sensitive-action ceremony still needs account-bound fresh proof, expiry and replay rejection. Old native credentials require regular account sign-in for browser recovery and cannot create provider connections; no silent email-based ownership transfer is allowed. Remote native-session APIs do not represent all Supabase devices. Internal administration uses only the explicit configured server credential; built-in defaults and user metadata no longer grant it.

Device grants now require durable RPC acknowledgement and cannot use memory after denial. Deployed database function semantics and cross-process acceptance remain separate from mocked route/repository tests. Provider callbacks are closed. Dated September 13 hosted acceptance verifies account entry, copied-token rejection after local logout and independent-session refresh; see [current state](../post-mortem/CURRENT_STATE.md). The broader cross-tab/failure matrix and later releases retain their separately recorded scope. This documentation reconciliation performs no new hosted authentication test. Read the incident before operational changes; do not use old process IDs or deployment receipts as current authority.

The [historical posture reference](knowledge/audits/2026-09-13-security-posture-legacy.md) preserves the former unverified matrix, timing, certification and diagnostic-grade claims as dated history. They are not current guarantees. Follow the [public information boundary](SECURITY.md); public documentation describes capability, not implementation.
