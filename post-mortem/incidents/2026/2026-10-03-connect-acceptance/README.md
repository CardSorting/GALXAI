# Connect real acceptance: browser defects and unavailable provider session

<!-- docs-scope: operational-record -->

INC-20261003-CONNECT was a SEV-2 acceptance blocker and is now recovered for the supervised cohort, owned by Codex during the controlled pass. Detection was October 3, 2026. The tested cohort contains one existing account, two reviewed first-party clients (one independent revocation control), and a local production-build application using the existing primary database and installed runtime. Wider customer impact is not established.

The [dated acceptance record](../../../releases/2026-10-03-connect-real-acceptance.json) separates actual browser/HTTP evidence from disposable fixtures. Connect migration 20261003131619 was validated and applied alone; the unrelated Orbit migration remains pending. The cohort received one explicit expiring inference entitlement. No hosted application release or account migration occurred.

Real browser use found an IP-loopback normalization defect in origin checks/account callback redirects and an invalid browser fetch receiver in the SDK. Narrow fixes and regressions were added. Consent and PKCE now succeed for the existing account; identity without entitlement is denied and unavailable inference preserves the connection.

At the initial observation, the installed runtime had live processes and fresh central authority, but no usable inference readiness. Both assigned provider credentials were expired. The established workflow requires manual sign-in inside the existing account desktop followed by explicit reconnect. This pass does not add renewal automation, substitute credentials, restart ownership, or bypass admission. See [credential enrollment](../../../../docs/maintainers/RELAY_CREDENTIAL_ENROLLMENT.md) and [FM-CTRL-002](../../../failure-modes/controller.md).

Live disconnect denied the first subsequent Nova request within 167 ms of its acknowledgement; refresh could not restore access. A separately consented client remained authorized. A fresh native grant also demonstrated refresh-reuse revocation. These are recorded in the [inspected HTTP evidence](../../../releases/2026-10-03-connect-real-http.json), with credential values omitted. The initial cohort closed with three revoked grants, a disabled temporary entitlement, and five retained `not_accepted` requests. The existing account and Media session remained intact. Local test processes are stopped; the shared provider runtime was not changed.

The [19:42 UTC recovery](../../../releases/2026-10-03-connect-provider-recovery.json) demonstrated that the fresh Pro sign-in was already stored. Save new sign-in confirmed it; one real Nova request then cleared the six retained failures. Two requests completed through the same existing provider account. An independently authorized browser client continued after native revocation. A client deadline and explicit streaming cancellation retained honest uncertainty; capacity remained bounded across clients and disconnect during streaming denied later admissions. The longer executor deadlines were not forced. No code, counter reset, cache deletion, provider-account replacement or runtime restart was needed for this recovery.

ACT-039 is completed for that bounded real lifecycle. Final cleanup leaves six revoked historical grants, disabled temporary entitlement, two completed and two unknown new requests, with the five earlier non-admissions retained. The account and Media remain intact. The thirteen earlier warnings retain their classifications/status/deadlines; ACT-001 still gates controlled hosted deployment. This recovery does not authorize a public launch.
